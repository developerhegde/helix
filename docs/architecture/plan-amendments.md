# Plan and HLD amendments — the standalone decisions

## Purpose

[`ai-builder-plan.md`](../../ai-builder-plan.md) and [`ai-builder-hld.md`](../../ai-builder-hld.md) were written on 2026-10-08 on the assumption that Helix delegates naming, property-file preparation, validation, the audit chain and tenant reads to Meridian. They are kept as written. This record lists every statement in them that the later decisions replace, what replaces it, and which document now governs. Where the plan or the HLD differs from this record, this record and the documents it names govern.

**The owner's decision of 2026-10-09.** Helix is standalone. In sub-phases B1–B5 it does not import, invoke, vendor or require Meridian, its files, its environment variables or its state. A future integration may enter only as an optional, version-pinned adapter that core Helix works without. Python 3.14 was fixed as the Helix language in the same change.

**The decisions of 2026-10-12.** They followed from the standalone design and from mapping the reference standard (`docs/mulesoft-development-standards.md`):

- Helix renders every environment's property files from the design bundle's key list; there is no `prepare` step.
- Two configuration layouts are supported: `environment_files` and `deployment_properties` (standards mapping decision D1).
- The client standards bundle is the source of client standards.
- The marks are `${HELIX_SET_<E>}` and `${HELIX_ENCRYPT_<E>}`.
- The branch name comes from the standards bundle's `review.branch_pattern` (D4), and the Mule file names from its `project.mule_files` (D3).
- Deployment property keys are declared in the design bundle only and are never written to the profile.

## How to read the tables

| Column | Meaning |
| --- | --- |
| Location | The section or heading, with a few words quoted so the statement can be found |
| What it says | The statement as the plan or the HLD makes it |
| What replaces it | The standalone design. *Withdrawn* means nothing replaces it in core Helix. *Not core* means an optional estate provider or adapter may add it later, and with none configured the estate is recorded as `not_checked` |
| Governed by | The architecture document in this folder, or the LLD file, that now holds the design |

File names without a path are in `docs/architecture/`. "LLD nn" is `docs/lld/nn-*.md`.
